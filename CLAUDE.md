# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository purpose

Personal dotfiles managed with **GNU Stow**. No build, no tests, no CI. Changes take effect on disk only after the relevant package is re-stowed (or the target file is already symlinked from a previous `stow`).

## Stow layout

Each top-level directory is a **stow package**: its subtree mirrors what should appear under `$HOME`. For example, `nvim/.config/nvim/init.lua` becomes `~/.config/nvim/init.lua` when `nvim` is stowed.

Packages: `nvim`, `shell` (contains `zsh` and `PowerShell` sub-packages), `term` (per-terminal sub-packages: `alacritty`, `ghostty`, `kitty`, `wezterm`, `windows_terminal`), `tools` (`agents`, `claude`, `devcontainer`, `herdr`, `hermes`, `opencode`, `pi`, `visidata`, `wsl` sub-packages), `scripts` (`~/.local/bin`), `arch` (Hyprland / waybar / greetd / qutebrowser), `gnupg`.

```sh
# from repo root
stow nvim              # link ~/.config/nvim → nvim/.config/nvim
stow -D nvim           # unlink
stow -R nvim           # restow (rebuild symlinks)
stow shell/zsh         # sub-packages need the subdir path
```

`.stow-local-ignore` keeps `README.md`, `installer.sh`, `docs`, `.git*` out of stowing. `.gitignore` excludes `lazy-lock.json`, `vfs.toml`, `settings.local.json`, and vendored tmux plugins — do not commit those even if regenerated locally.

## Neovim config (the bulk of this repo)

**The active config is `nvim/.config/nvim/`** — a kickstart.nvim fork. The siblings `nvim-dev/`, `nvim-lazy/`, `nvim-minimax/`, `nvim-scratchpad/` are experimental / scratch. Do not edit those unless the user names one explicitly; switch with `NVIM_APPNAME=nvim-dev nvim` (aliased as `vimdev` in `.zshrc`, or the `vv` fzf picker).

### Load order — `init.lua`

```
config.options → config.autocmds → config.usercmds → config.keymaps →
config.functions → config.todo_tasks → config.highlights →
lazy-bootstrap → lazy-plugins
```

`config.snippets` is currently commented out. **Leader is `<Space>`** and is set in `config/options.lua` _before_ `lazy-plugins` loads — preserve that ordering if you add setup steps.

### Plugin system

- `lua/lazy-bootstrap.lua` clones lazy.nvim into `stdpath('data')/lazy/` on first run.
- `lua/lazy-plugins.lua` calls `require('lazy').setup({ { import = 'plugins' }, ... })`, so **every file in `lua/plugins/*.lua` is auto-imported** and must return a lazy.nvim spec (or list of specs). Adding a new plugin = drop a new file in that folder; no registration needed elsewhere.
- `lua/plugins/inactive/` holds disabled specs — it is _not_ imported, so files there are inert until moved up one directory.
- Plugin versions pinned by `lazy-lock.json` (gitignored). Use `:Lazy sync` / `:Lazy update` inside Neovim rather than hand-editing specs.

### Formatting

Lua is formatted with **stylua** per `nvim/.config/nvim/.stylua.toml` (2-space indent, 160 col, single quotes, no call parens). Run `stylua <file>` before committing Lua changes.

### WSL specifics

`tools/wsl` (stow it on WSL only: on native Linux it would shadow the real tools) holds clipboard shims for `xclip`, `xsel`, `wl-paste`, `wl-copy` on top of win32yank, plus `wsl-clipboard-image` (PowerShell), so `xclip -t TARGETS` / `-t image/png -o` and `wl-paste -l` / `--type image/png` hand Windows clipboard images to tools such as Claude Code's Alt+V paste; non-text types they can't serve exit 1.

`config/options.lua` swaps in `win32yank.exe` for clipboard when `has('wsl')` is true — if clipboard breaks, confirm `win32yank.exe` is still on `$PATH`. `.zshrc` strips `/mnt/c` entries from `$PATH` on shell init, so Windows executables shelled out to from zsh must be referenced by absolute path.

## Shell (zsh)

`shell/zsh/.zshenv` puts `~/.local/bin` on PATH for every zsh, including non-interactive `ssh host cmd` (herdr saved machines, `--remote`). `shell/zsh/.zshrc` launches or attaches herdr at login (tmux where herdr is missing), bootstraps **zinit**, loads **powerlevel10k** (config in `.p10k.zsh`), and turns on **vi-mode** bindings. Integrations wired via `eval`: `fzf`, `zoxide` (bound as `cd`), `direnv`. direnv stays off in agent shells, since `.envrc` files read secrets with `pass`: panes `ha` creates (`--env HERDR_AGENT_PANE=1`), panes herdr restored with an agent name (herdr restores the name but not the env), and Claude's own shells (`CLAUDECODE`). Notable aliases: `vim`→`nvim`, `cat`→`bat`, `e`→`yazi-cwd` (cd-to-yazi helper), `lg`→`gpg-unlock-lazygit`.

- **herdr** (`tools/herdr`) is the multiplexer; `.zshrc` starts it at login. `ha [--host] NAME [claude args]` spawns a named Claude agent in a new tab (labelled NAME) of the caller's workspace — through `dclaude --new` by default, plain host `claude` with `--host`; `hfork [NAME]` (run inside Claude as `!hfork`; NAME defaults to `<agent>-fork`) forks the pane's conversation into a new tab with `claude --resume <id> --fork-session`, which herdr tracks and can resume — unlike `/fork`, whose background session has no pane.
- **herdr config** lives in `tools/herdr/.config/herdr/config.toml` (prefix `ctrl+k`; custom keys: `prefix+t` ticket board (`ht` popup in the pane's directory), `prefix+c` new tab (no name prompt), `prefix+shift+c` rename tab, `prefix+shift+r` runs `hrun` in a popup (herdr's `reload_config` unbound; `hrun` lists "herdr reload"), `prefix+tab` last tab (local plugin `plugins/last-tab`: herdr has no `last_tab` action; linked by `setup-agents`, `cycle_pane_next` unbound), `prefix+n` nvim in a new tab at the pane's directory (via `mux-open`), `alt+left|right` previous|next tab, `alt+down|up` next|previous workspace, `prefix+ctrl+r` clear pane screen + scrollback, `j`/`k` workspaces and `J`/`K` panes in the `prefix+w` picker, `prefix+alt+n|p` focus next|previous agent, `prefix+1..9` (default) and `alt+1..9` tab by index, `prefix+m` runs `hbreak` via `[[keys.command]]`: moves the pane to a new tab, named after its agent if any; `prefix+%` runs `hflip`: toggles a two-pane tab between side by side and stacked; `prefix+a` jumps to the toast's agent (`open_notification_target`, moved from its default `prefix+o`, which runs `hw`), which also reaches other machines (`hlast`, focusing the blocked or last-finished agent on the current machine only, is unbound); `prefix+i` opens lazygit in a popup at the pane's cwd (`hlazygit`, a reused per-repo lazygit tab, is unbound); `prefix+s` opens `hp` in a popup, herdr's Settings moved to `prefix+shift+s`; `prefix+p` / `prefix+shift+p` run `open-pass` copy / show in a popup, as in tmux (previous tab only on `alt+left`, rename pane on `prefix+ctrl+p`); `prefix+v` runs `hsplit`: split right, coupled to the tab's agent with `hcouple` (plain split on `prefix+shift+v`); `prefix+e` opens yazi in a popup at the pane's cwd, `prefix+alt+e` yazi on the VPS over SFTP (`yazi sftp://vps`, from `[sftp.vps]` in the gitignored `~/.config/yazi/vfs.toml`, desktop only; elsewhere the popup says it's missing), `prefix+backtick` a scratch zsh popup there, edit-scrollback moved to `prefix+shift+e`; `prefix+o` / `prefix+shift+o` open `hw` in a popup (tmux-windowizer port: fzf a file below the pane's cwd / under ~, opened in nvim or visidata in a new tab); copy mode on `prefix+f`). The tab bar shows usage via `hlimits`: `✻` Claude's 5-hour window from `~/.cache/claude-limits.json` (written by `statusline-command.sh`) and `◇` OpenCode Go's, fetched over the tailnet from the VPS's `oclimits` file (URL in the untracked `~/.config/hlimits/opencode-url`), as plain percentages with time to reset; the status line also reports each session's context use and model as pane metadata `$ctx` and `$model`; the agent sidebar (`ui.sidebar.agents.rows_by_agent.claude`) shows `$ctx`, coloured by level. Inside herdr the status line prints nothing; it only reports. Check key defaults/conflicts against `https://herdr.dev/llms.txt` (links the per-version `config-reference.json`); apply with `herdr config check && herdr server reload-config`.
- **`hp`** is the project picker (herdr's tmux-sessionizer): one fzf list of open workspaces, past Claude chats (host and dclaude, newest 10 per project, resumed via `ha --workspace` into the project's workspace), projects opened before (`~/.local/state/hp/history.json`) and every folder. A new workspace runs the project's `.herdr-start` (`label: command` per line, `ha` starts the agent named after the project), else `.tmux-start`'s command, else `agent: ha` when there's a `CLAUDE.md`.
- **`hcouple`**: typing `hcouple` (zsh function, `.zshrc`) in a shell pane couples it to the agent in the same tab (or `hcouple NAME`, `hcouple off`). Each finished command, with exit status and output read back from herdr, is appended to `<agent's config dir>/hcouple/<session>.log` (`~/.claude` or dclaude's state dir), and the agent's `UserPromptSubmit` hook `hcouple-hook.sh` hands it over with the next prompt. Logging never wakes the agent (each wake-up re-reads its whole context); `hcouple wake` types a short note into it once it is idle (a detached waiter covers a busy agent). Trivial commands (`cd`, `clear`, `ls`, `pwd`, `yank` ...) aren't logged, and the session is looked up by agent name at each command, so the log follows the agent after a `/clear`. For what agents can't run themselves, like sudo with a password. `yank` (zsh function) copies the previous command's full output to the clipboard via `clipboard-copy`, any length, without rerunning it: herdr's pane read, cut between the last two `❯ ` lines (powerlevel10k's transient prompt leaves each finished prompt as one such line).
- **`hmail`** (`scripts/`, Python, stdlib only): messages between agents that never type over the human. `hmail send NAME TEXT` appends one line to `~/.cache/hmail/NAME`, signed with the sender's herdr agent name (`HMAIL_FROM` names a sender without one, as `hpr` does with `human`) (writable in `abox`; a sandbox that can't write there falls back to `herdr agent prompt`, as does a missing daemon). `hmail daemon` (`hmail.service`, `scripts/.config/systemd/user/`, enable once per machine with `systemctl --user enable --now hmail.service`) types the mail in as `[hmail] ...` once the agent is idle, its input box isn't holding a draft (focused or not: Claude's `❯` line, its `Try "..."` placeholder counting as empty; OpenCode's `┃` lines above the agent/model line; pi's lines between its last two plain rules; for any other harness the screen unchanged since the agent turned idle) and, when the pane is focused, the screen has been still for 15 s. Claude's `UserPromptSubmit` hook `hmail take --hook` attaches waiting mail to the human's next prompt instead. Workers' reports to their lead (every team: Claude's `SendMessage` addresses Claude's own session names, such as `homelab-a7`, not the herdr name `lead start` puts in the pointer), the ux-designer's, and setup-admin's briefs to `homelab-lead` go through it; leads still brief their own workers with `herdr agent prompt`, since nobody types in worker panes. `hmail list` shows what waits.
- **No background service in herdr panes**: `.zshrc` exports `CLAUDE_CODE_DISABLE_AGENT_VIEW=1` when `HERDR_ENV=1`. Otherwise Claude hosts every session in shared background workers carrying the env of whichever pane started the service, so herdr would track a viewer (no resume, no `hfork`, hooks hitting a stale pane). Background jobs (`claude agents`, `--bg`) are only available outside herdr.
- **`dclaude`** (`scripts/`) runs Claude in the project's devcontainer, falling back to `tools/devcontainer/.config/devcontainer/default/devcontainer.json`. The container gets its own `~/.local/share/dclaude/claude` state, with host config copied in each run. Login: a long-lived token of its own (`claude setup-token`, saved to `~/.config/dclaude/oauth-token`, 0600; exported as `CLAUDE_CODE_OAUTH_TOKEN`), so containers never race the host's login on refresh-token rotation; without it, the host's `.credentials.json` is mounted writable as before (and goes stale after Docker Desktop restarts). It sets `HERDR_AGENT=claude` on the host-side wrapper so herdr detects it, and `DCLAUDE=1` inside. Its SessionStart hook `hooks/dclaude-resume.sh` re-reports the session to herdr with `dclaude --resume <id>` as resume command, since herdr would otherwise resume with host `claude`. Without claude args it continues the project's latest container session (`--new` starts fresh). Bash runs in Claude's sandbox with `/herdr` (the socket dir) hidden, so commands can't drive host panes while hooks still report; it needs user namespaces, which the default devcontainer gets from `seccomp-userns.json` (Docker's default profile + namespace syscalls) via `runArgs` — project configs need the same, else dclaude warns and runs unsandboxed. Docker doesn't stop exec'd processes when the client goes away, so each run tags its container processes with `DCLAUDE_RUN` and a detached watcher stops them once the run's host side ends (closing the tab); leftovers whose watcher died too are reaped at the next start. Before starting Claude it sets the container's global git identity to the host's for the repo, turns on `worktree.useRelativePaths` (container paths in worktree links break git on the host) and turns git hooks off (`core.hooksPath /dev/null`: pre-commit environments are slow to build and the sandbox cannot build them; host commits still run them). Per-project extras are opted into on the host in `~/.config/dclaude/projects.json` (`tools/devcontainer`, keyed by project path, never read from the repo): `files` copied in at the same absolute path (0600, each run), `env`, sandbox `allowedDomains` (via `--settings`, as the state's settings.json is shared) and a `setup` command run outside the sandbox. It also passes `TERM`/`COLORTERM` through: docker exec's `TERM=xterm` makes Claude round theme colours to 16 (rose dot → white).
- **Worktrees**: the `WorktreeCreate`/`WorktreeRemove` hooks route every Claude worktree through `herdr worktree create` (`~/.herdr/worktrees/<repo>/worktree-<name>`, shown as a herdr workspace). Without a running herdr server, or under `DCLAUDE=1`, they fall back to `git worktree add` under `<repo>/.claude/worktrees/`.

On a new machine: clone, then run `scripts/.local/bin/setup-agents`. It checks prerequisites, installs Claude, herdr and the devcontainer CLI when missing, stows `scripts` and `tools/{claude,herdr,devcontainer}` with `--no-folding` (backing up real files in the way), runs `herdr integration install claude` and writes the herdr skill. Rerun it after pulling.

## Install / bootstrap

`installer.sh [--check] [--groups core,nvim,extra] [--nvim] [--yes]` installs the missing commands listed in `packages.tsv` (command, group, Arch package, apt package, note) with pacman or apt, prints the note for tools a distro doesn't package, and with `--nvim` runs Lazy sync and `MasonToolsInstallSync` headless. Groups: `core` (shell and scripts), `nvim` (Neovim, the cargo/go/node/tree-sitter its plugin builds and mason need), `extra` (opt-in desktop tools such as `pass`, which must stay off servers). When a config starts needing a new tool, add it to `packages.tsv`. Then `setup-agents` (above) stows the configs and installs the agent tooling. The older README sections are manual notes.
